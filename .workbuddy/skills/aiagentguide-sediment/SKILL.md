# AiAgentGuide 沉淀流水线（每次新读文章后照做）

> 这份 skill 的定位：**一条可以反复执行的 runbook**。
> 触发场景是"用户又读了一章/一篇文章"，产出是"整条四层流水线 + 所有进度文档都同步到位"。

一句话：`0-记录区/` 是原料，`1-知识库/` → `2-面试题库/` → `3-测验/` 是三层加工，最后**把所有声称的数字改成一致的**。

---

## 每次照做的 7 步（总览）

| # | 步骤 | 产出 | 最容易漏的 |
| :-- | :--- | :--- | :--- |
| **0** | 同步 + 盘点 | 拉到最新代码，确认本轮到底新增了什么 | ⚠️ 上游可能只做了前几层 |
| **1** | 记号扫描 | 列出本轮全部 `==…==` / `~~错题~~` / `> 疑问：` | 漏一个 `==` 就少一组派生题 |
| **2** | 沉淀知识库 | 每章 1 条 `NN-主题.md` | 🔆 延伸 / ❓ 解答没落进去 |
| **3** | 衍生面试题 | 开放题 `O-NN` + 选择题记录题 | 三处索引没同步 |
| **4** | 扩测验题库 | `bank.json` + 章节下拉 | `s:1` 遗漏、下拉漏项 |
| **5** | 同步进度文档 | 4 处文档的数字 | 数字不自洽 |
| **6** | 验收 + 收尾 | 测试全绿 + 报告 `git status` | 擅自 commit |

---

## 路径与结构

```
0-记录区/   采集层：chNN-章节名.md（meta / 八股 / 思考题 / ==强化== / ~~错题~~ / > 疑问：）  ← 用户的地盘
1-知识库/   沉淀层：NN-主题.md（30秒结论 · 机制 · 易错点 · 📌你的原文 · 🔆强化延伸 · ❓疑问解答）
2-面试题库/ 冲刺层：01-选择题-原题与解析.md · 02-开放题-口述版.md · README.md
3-测验/     测验层：bank.json（唯一数据源）→ index.html（build.js 生成物）
```

---

## 步骤详解

### 0. 同步 + 盘点（**先做这步，别急着动手**）

```bash
export PATH="/c/Windows/System32:/usr/bin:/bin:$PATH"   # Windows/bash 必做，否则 shim 报 dirname: command not found
git fetch origin && git status -sb                       # 看本地落后多少
git pull --ff-only origin main                           # 本地有未跟踪文件也能快进
git config core.quotepath false                          # 可选：让中文文件名在 git 输出里不显示成 \346\265\213
```

然后**按四层逐一核对完成度**——上游（或上一个会话）做完的沉淀常常不完整：

1. `bank.json` 的章节分布 **vs** `0-记录区/` 现有章节
2. `s:1` 题数 **vs** 知识库各条目里的 🔆 强化延伸处数
3. README / 根 `index.html` 声称的数字 **vs** 实际统计

真实案例见文末「坑 ①」：远端提交做了记录区 + 知识库 + 面试题库，**唯独漏了测验层**。

盘点新记录：
- `git status` + Glob `0-记录区/ch*` 找出新增章节。
- 逐个检查记录文件，修正常见脏数据：**缺 `.md` 后缀**（用 `git mv`）、meta 里章号写错（如 ch07 写成"第 8 章"）、章号占位符（"第 X 章"）、记录日期缺失。

### 1. 记号扫描（决定后面要做多少事）

用 Grep 工具（**不要用 bash 的 `grep -o/-c`**，本机行为异常）逐类扫，把结果记成清单再动手：

| 记号 | 搜索模式 | 要产出什么 |
| :--- | :--- | :--- |
| `==……==` | `==[^=\n]{2,40}==` | 知识库每处加「🔆 强化延伸」（含 3~4 问追问链）+ **派生测验题打 `s:1`** |
| `~~A~~ B` | `~~[^~\n]+~~` | 面试题库错题表 → 归纳根因 → 写「错题根治」→ 进测验错题池 |
| `> 疑问：` | `>\s*疑问：` | 知识库「❓ 你的疑问解答」正面回答 + 自测题 |

> ⚠️ `==` 会误命中代码块里的比较运算与表格分隔线，**只统计正文/八股卡里成对的 `==…==`**。
> 把本轮每处 `==` 写在纸上（例：ch11 的 `==Q6==` / `==Q8==` / `==Q13==` → 3 处 = 3 道派生题），
> 这是后面第 4 步和验收时对账的依据。

### 2. 沉淀知识库（`1-知识库/`）

每章产出 **1 条** `NN-主题名.md`（编号顺延 `1-知识库/README.md` 总表），**按知识点重组而非照抄章节**。每条包含：

- 30 秒结论（一句话讲清是什么 / 为什么）
- 机制展开（分点、含关键数字与阈值）
- 易错点 / 对比表
- 📌 原文落点（指向 `0-记录区/chNN §x.y` / 八股 Qn）
- 🔆 强化延伸 ← 用户原文的 `==…==` 标记，含**追问链**（3~4 问）
- ❓ 疑问解答 ← 用户原文的 `> 疑问：`，必须正面回答并给自测题

### 3. 衍生面试题（`2-面试题库/`）

- `02-开放题-口述版.md`：每章 2 道，编号顺延 `O-NN`，格式 `### O-NN｜标题` + `**级别**/**来源**/**条目**` + 参考回答 + 追问链 + 雷区。
  六手法：**A** 去选项化 / **B** 追问原理 / **C** 落到工程 / **D** 加边界 / **E** 干扰项 / **F** 反向假设。目标一半 L4（能说出"什么时候不适用"）。
- **三处必须同步**：① 文末「使用建议」表；② 文件头 `> 更新：` 的日期与题数；③ 「速查索引」补本批表格（H2 = 批次，H3 = 题目，**别混层级**）。
- `01-选择题-原题与解析.md`：新增「第 N 部分 · chXX ~ chYY 记录题」，并更新「易错题清单」。
- `README.md`：开放题索引补对应批次。

### 4. 扩测验题库（`3-测验/`）

- **只编辑 `bank.json`**（唯一入口）。字段：`id / c(章节) / concept / w(权重1~5) / t(题型) / lv(L1~L4) / q / o / a / e / s(强化派生的题标 1)`。
- **加题的推荐姿势**：写个临时 node 脚本 `JSON.parse → push → JSON.stringify(bank, null, 2) + '\n'` 写回，
  diff 会是**纯插入**（ch10~ch12 那次是 +247/-0，格式零扰动），比手改 JSON 安全；跑完删掉临时脚本。
- **只校验新增题**：4 个选项、单选 1 个答案、多选 ≥2、无重复；全量只校验 id 唯一与答案索引不越界（既有题可能不是 4 选项）。
- **`==` 派生的题必须打 `s:1`**（易漏！漏了「🔆强化专项」与章节筛选就对不上）。
- 顺便把 `3-测验/index.html` 的章节筛选下拉补上新章节，以及 `<title>` 里的章节区间。
  - ⚠️ **测试不会替你查下拉**：`test-engine.js` 的 `chapters` 取自 `BANK.map(x => x.c)`，
    只验证"各章筛选出的题数 = 题库统计"，**不校验 HTML 里有没有对应 `<option>`**。
    「测试全绿 + 下拉漏项」完全可能，必须手工核对「题库章节 ↔ 下拉项」双向一致。
- 然后：`node tools/build.js`（重建 `BANK_INLINE`）→ `node tools/run-tests.js`。
- `tools/export-bank.js` 是**覆盖写**的重算权重工具，必须显式 `--force`，日常勿用。

### 5. 同步进度文档（4 处，数字必须自洽）

| 文件 | 要改的地方 |
| :--- | :--- |
| `1-知识库/README.md` | 覆盖声明 · 知识点总表 · 🔆 清单 · 📌 原文落点表 · ❓ 疑问表 · 关系图 |
| `0-记录区/ToPractice.md` | 给新章节补 1~2 个**可验收**的动手项 |
| 根 `README.md` | 「当前进度」（知识库条数 / 选择题 / 开放题 / 测验题 / 疑问数）+ 本批整理说明 |
| 根 `index.html` 工作台 | meta chips · 最新一批说明 · 目录树 · 章节地图（新章标「已记录」+ 知识库落点）· 文件清单 |

> **算术必须自己验一遍**：测验题 = 章节记录题 + 强化派生题。
> 历史踩坑：写过"107 = 原题 90 + 派生 26"（90+26=116，不成立）。

### 6. 验收 + 收尾

交付前逐条打勾：

- [ ] `node tools/build.js` 成功，且**内联题数 = `bank.json` 题数**
- [ ] `node tools/run-tests.js` → **121 项全绿**（引擎 25 / 渲染 15 / 部署 5 / e2e 24 / 云同步 36 / 布局 16）
- [ ] **题库章节 ↔ `index.html` 下拉 option 双向一致**（脚本核对，测试不覆盖）
- [ ] `s:1` 题数 **=** 本轮扫描到的 `==` 处数（加上历史累计）
- [ ] 三处数字一致：`bank.json` 实际统计 / 根 `README.md` / 根 `index.html`
- [ ] 临时脚本已删（`tools/_*.js` 之类）

收尾约定：
- 改动**默认不 commit**，先把 `git status` 报给用户，问是否提交。
- 用户说「提交并推送」后，用 `gh run list -R Dithob/AiAgentGuide -L 3` 复查 **GitHub Pages 构建**（用户管它叫「runpage」）是否 `success`。
- 完事按 `memory_and_skills` 约定追加当日工作日志。

## 坑 ①：上游提交常常只做了前几层（2026-09-19 踩过）

「记录区 → 知识库 → 面试题库 → 测验」四层，**每次接手都要逐层核对**，别默认"已经做完了"。

典型案例：远端 `64b9c85` 做完记录区 ch10~ch12 + 知识库 23~25 + 面试题库（选择题 90 / 开放题 58），
**唯独没动 `3-测验/bank.json`** —— 题数停在 107、章节筛选停在 ch09、README 的数字滞后。
更隐蔽的是：知识库 24 里已经写了 🔆 强化延伸，等于**承诺了派生题却没出题**（`s:1` = 0）。

→ 所以第 0 步的三组比对不能省。

## 坑 ②：「测试全绿」不等于「下拉没漏项」（2026-09-19 踩过）

`test-engine.js` 的章节列表是从题库自己推出来的（`BANK.map(x => x.c)`），
它验证的是"按 chXX 筛选能筛出题库里该章节的题"，**完全不看 HTML 里有没有那个 `<option>`**。
所以加完章节，必须单独跑一次「题库章节 vs 下拉项」的双向核对。

## 坑 ③：GitHub Pages 的 Jekyll 会吃掉 Jinja2 语法（2026-09-18 踩过）

线上站点（`https://dithob.github.io/AiAgentGuide/`）发布源是 `main` 根目录，GitHub **默认用 Jekyll 处理所有 Markdown**。笔记里写着 Jinja2 模板语法（`{% if %}` / `{% for %}` / `{% extends %}` / `{{ var }}`）时，Jekyll 会当成 Liquid 模板解析并报：

```
Liquid syntax error (line N): Syntax Error in tag 'if' - Valid syntax: if [expression]
```

→ `pages-build-deployment` 失败，**站点静默冻结在旧版本**（push 本身是成功的，所以不易察觉）。

当前用两道保险挡住，**别删仓库根这两个文件**：

| 文件 | 作用 |
| :--- | :--- |
| `.nojekyll` | 让 GitHub 直接跳过 Jekyll 构建（首选） |
| `_config.yml` | `exclude` 掉 `0-记录区/`、`1-知识库/`、`2-面试题库/` 等源目录，只发布两个静态页 |

正常的 Pages 构建步骤只有 `Checkout` → `Upload artifact`（**没有** `Build with Jekyll`）。
若某次看到 Jekyll 步骤回归或 run 失败，先查新写的 Markdown 里有没有新的 `{{ }}` / `{% %}`。
