## 第四章 · Prompt 工程

- [ ] **把第一版 Prompt 改写成 Jinja2 模板**

  - 过关标准：能把「有工具 / 无工具」两套话术合并进一个模板文件。
  - 参考：[kb/17 §三](../1-知识库/17-Prompt模板化与PromptOps.md)

- [ ] **给自己项目的 System Prompt 画一张分区表**

  - 参考：[kb/17 §五](../1-知识库/17-Prompt模板化与PromptOps.md)

## 第七章 · 记忆系统

- [ ] **跑通一次「写入 → 检索 → 注入」闭环**
  - 用 Chroma（嵌入式、零配置）存一批历史摘要，按 query 检索 Top-K 注入 Prompt。
  - 重点不是跑通，是**观察召回噪声**：故意把 K 调到 10，看上下文怎么被污染。
  - 参考：[kb/20 §一、§四](../1-知识库/20-Agent记忆系统.md)

- [ ] **给召回打分加上时间衰减**
  - 实现 `recall_score = 相似度×w1 + e^(-λΔt)×w2 + log(1+成功召回次数)×w3`，对比"只看相似度"时的召回结果差异。
  - 参考：[kb/20 §三](../1-知识库/20-Agent记忆系统.md)

## 第十一章 · RAG

- [ ] **搭一条最小混合检索链路**
  - 同一批文档建两路索引：BM25（`rank_bm25` 即可，零依赖起步）+ 向量；按 **BM25 0.4 / 向量 0.6** 加权融合。
  - 过关标准：能举出一个**纯向量检索失败、BM25 救回来**的具体 query（提示：带版本号/型号的词，如 "GPT-4o"）。
  - 参考：[kb/24 §二](../1-知识库/24-RAG检索增强生成.md)

- [ ] **给检索加一次可量化的评估**

  - 过关标准：能说出召回率与精确率为什么经常此消彼长、你更看重哪个。
  - 参考：[kb/24 §七](../1-知识库/24-RAG检索增强生成.md)

## 第十二章 · LLM-Wiki

- [ ] **跑一次知识库 Lint**

  - 过关标准：能说出"知识库腐烂"的三种典型症状，以及 Lint 为什么必须定期跑而不是一次性。

- [ ] **把一次摄入拆成两步**

  - 过关标准：能说清两步拆分相比"一步到位"多换来了什么。
