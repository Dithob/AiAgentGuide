# 10 · 可观测性与成本

代码：`maodingcode/core/observability.py`

## 要回答的三个问题

没有埋点的 Agent，遇到这些问题只能靠猜：

1. **这次任务花了多少钱？** → token 用量 + 缓存命中率
2. **慢在哪一步？** → 模型耗时 vs 工具耗时
3. **模型为什么选了这条路？** → 步数与工具调用序列

## 埋点

```python
tracer.record_model_call(step, response, elapsed, sent_messages)
tracer.record_tool_call(name, ok, elapsed, size)
```

分别记进 `steps: list[StepRecord]` 和 `tools: list[ToolRecord]`。
用 dataclass 而不是裸 dict，是为了 `summary()` 里做聚合时不用防御性取值。

### 模型耗时 vs 工具耗时

这两个数字分开很有价值：

| 现象 | 含义 | 对策 |
|---|---|---|
| `model_seconds` 占 90% | 正常，模型就是这么慢 | 换更快的模型 / 开流式输出改善体感 |
| `tool_seconds` 占 90% | 工具实现有问题 | 查是不是在跑全量测试、有没有串行网络请求 |
| `wall - model - tool` 很大 | 等用户确认 / 等输入 | 减少确认次数，或用 `[a] 全部允许` |

### 缓存命中率

```python
@property
def cache_hit_rate(self) -> float:
    if not self.usage.prompt_tokens:
        return 0.0
    return self.usage.cached_tokens / self.usage.prompt_tokens
```

这是最容易被忽视但影响最大的指标。多数服务对缓存命中的输入 token
只收 10% 的费用（`cache_discount = 0.1`）。

命中率低通常意味着**系统提示前缀不稳定**——比如每轮都把时间戳、
随机数、变化的工具列表放在提示开头，导致前缀匹配全部失效。

本项目的应对：`ContextManager._rebuild_system_prompt()` 按固定顺序拼接，
静态内容（身份、环境）在前，动态内容（记忆、技能索引）在后。

## 成本估算

```python
def cost(self) -> float | None:
    cached = self.usage.cached_tokens
    fresh_input = max(self.usage.prompt_tokens - cached, 0)
    in_cost = (fresh_input * price_in + cached * price_in * cache_discount) / 1000
    out_cost = self.usage.completion_tokens * price_out / 1000
    return in_cost + out_cost
```

**不硬编码价格表。** 价格会变，写死在代码里迟早过期。
改成从配置读：

```toml
[model]
price_in_per_1k = 0.002
price_out_per_1k = 0.008
```

没配置就返回 `None`，`/cost` 里显示"未配置单价"，而不是显示一个错数。

## 调用链落盘

```python
tracer.dump(".maodingcode/traces/2026-09-19-1652.json")
```

产物包含 summary、每一轮的 token 明细、每一次工具调用的成功/耗时/输出大小。

用途：

- 排查"这次为什么跑了 20 步"——翻工具调用序列，看是不是原地打转；
- 做回归对比——改了系统提示后，把两次的 trace 摆一起看 token 变化。

## 延伸：生产环境该补什么

本项目只做了"攒指标 + 落盘"。生产环境还需要：

| 能力 | 为什么需要 |
|---|---|
| 分布式追踪 | 一次任务跨多个服务时，需要 trace_id 串联 |
| 实时告警 | 单次任务 token 超阈值 / 失败率突增 |
| 采样存储 | 全量落盘成本高，按比例采样或只存异常样本 |
| 评测集回归 | 固定输入跑一遍，对比输出质量与成本变化 |
| 用户反馈关联 | 把"回答不好"的反馈与具体 trace 关联起来定位 |

这些都是 `23-Agent评估与可观测性` 那一章展开的内容。
本项目的定位是把**数据采集**这件事做扎实——
后面接任何 tracing 后端，都只是在 `Tracer` 基础上加一个 exporter。
