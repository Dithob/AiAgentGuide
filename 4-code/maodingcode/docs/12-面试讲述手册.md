# 12 · 面试讲述手册

前面 11 篇是设计文档。这一篇讲**怎么把它讲出去**——
用 1 分钟、5 分钟、15 分钟三种长度，讲同一个项目。

---

## 一分钟版（电梯陈述）

> MaoDingCode 是我写的一个本地 AI 编码助手，核心是 Agent 运行时。
> 一条链路：上下文装配 → 模型决策 → 工具执行 → 结果回灌，循环到模型不再需要工具。
>
> 我花了比较多精力在三件事上：
> **一是权限**，危险命令用确定性黑名单拦，写操作按可逆性分级，
> 而不是让模型自己判断该不该做；
> **二是上下文**，两级裁剪——先折叠旧工具输出，再整轮丢弃，
> 配合固定的系统提示前缀把缓存命中率做到 85% 以上；
> **三是可扩展**，外部能力走 MCP 协议动态注册，方法性知识走 Skills 按需加载，
> 加工具和加技能都不用改引擎代码。

**要点**：一句话说清是什么，然后立刻抛出三个"我花精力解决的问题"。
不要一上来讲目录结构。

## 五分钟版

### ① 背景与目标（30 秒）

在读 AI Agent 相关教程时意识到：Agent 的门槛不在"调通 API"，
而在**运行时工程**——循环怎么收敛、上下文怎么不爆、工具怎么不闯祸。
所以我写了一个完整的实现，目标是自己能讲清楚每一个设计决策。

### ② 架构（1 分钟）

分层：界面 / 装配 / 引擎 / 能力 / 策略 / 接入，依赖严格单向。

三个关键抽象：

- `Provider` —— 把模型调用归一化成 `chat(messages, tools) -> ChatResponse`，
  所以测试可以换成假 Provider，**不联网就能跑 16 个用例**；
- `Tool` —— 名字 + 描述 + JSON Schema + 执行函数 + 可逆性；
- `Policy` —— `check(tool, args) -> ALLOW / ASK / DENY`，确定性查表。

引擎不打印任何东西，只发事件。想换界面只改 `ui/render.py`。

### ③ 三个我认为最有价值的点（2.5 分钟）

**上下文裁剪的两级策略**

早期工具输出先折叠成一行摘要，再不够就整轮丢弃。
顺序不能反——丢单条消息会拆散 `tool_call` / `tool_result` 配对，
多数服务会直接返回 400。
丢弃必须整轮、且必须持续丢到装得下为止（这里踩过坑，见下）。

系统提示按固定顺序拼接，静态内容在前、动态内容在后，
保证前缀稳定以命中 prompt cache，命中率能到 85%+。

**确定性的权限模型**

模型只负责"想做什么"，"能不能做"由策略层决定。
16 条危险命令正则黑名单，优先级高于一切，`auto` 模式也拦。
路径沙箱比较 `resolve()` 后的路径，防 `../` 和符号链接逃逸。
查不到工具性质时按"写操作"处理——fail-closed。

**两套扩展机制的分工**

MCP 管"能做什么"，Server 自描述工具清单，启动时拉取注册，
Agent 完全不知道工具是内置还是外挂。
Skills 管"该怎么做"，`SKILL.md` 按需加载——索引常驻系统提示，
正文等模型判断相关时才读进来。加 100 个技能系统提示只涨几 KB。
单个 MCP Server 挂掉只记录不中断启动。

### ④ 一个真实的 bug（1 分钟）

上下文裁剪第一版里，整轮丢弃只丢了一轮就返回。
测试用 6000 token 历史、4500 token 预算时暴露出来：丢一轮省 500，
但超出量是 1500，丢完还是超窗。
改成用前缀和逐个试算切点，找到第一个装得下的位置。

这个 bug 让我意识到：**所有"裁剪/限流/退避"逻辑都要写成
`while 不满足约束`，不能写成 `if 不满足处理一次`。**

## 十五分钟版 · 深挖问题清单

准备好被追问这些。**答不上来的不要写进简历。**

### 关于 Loop

| 问题 | 答题方向 |
|---|---|
| 循环怎么退出？ | 四个条件：正常收敛、`max_steps`、用户中断、失败熔断 |
| 为什么不直接 kill 而用 abort 标志？ | 工具执行到一半被打断会留半成品，在轮次边界退出状态才是干净的 |
| 模型反复调用同一个失败工具怎么办？ | 熔断键是 `工具名 + 排序后的参数`，连续 3 次相同调用才熔断，参数变了就重置 |
| 工具抛异常会怎样？ | 被兜住转成文本回灌，模型自己纠偏。工具异常绝不能掀翻循环 |
| 为什么工具结果必须是字符串？ | 统一序列化点，避免各处漏掉 `ensure_ascii=False` 导致中文变转义序列 |

### 关于上下文

| 问题 | 答题方向 |
|---|---|
| 预算怎么算？ | `window * 0.75 - 系统提示 - 工具 schema`，再取 `max(budget, 2000)` 下限 |
| 为什么预留 25%？ | 输入塞满后模型没有空间生成，会截断或报错 |
| 为什么先折叠后丢弃？ | 折叠只改内容不动结构；丢消息会拆散 tool_call 配对导致 400 |
| 最近几轮为什么要保护？ | 模型要靠最近完整上下文接着干活，折叠掉等于蒙住眼睛 |
| 怎么提高缓存命中率？ | 系统提示前缀稳定：静态在前、动态在后 |
| 为什么不用向量检索做记忆？ | 检索解决"大"不解决"准"。项目约定是结构化小文本，全量注入更准 |
| 为什么工具多时要切索引模式？ | schema 每轮都发，50 个工具 = 1 万 token/轮，且降低选对率 |

### 关于安全

| 问题 | 答题方向 |
|---|---|
| 为什么不信任模型的危险判断？ | 模型可以说服自己任何事。策略必须确定、可审计、模型改不动 |
| `auto` 模式还拦什么？ | 危险命令黑名单，优先级高于模式 |
| 怎么防 `../` 逃逸？ | 比较 `resolve()` 后的路径，用 `relative_to` 而不是字符串前缀 |
| 确认弹窗怎么设计？ | 命令原文完整可见 + 写明拦截原因 + 提供"全部允许"避免用户烦到关掉权限 |
| 黑名单能被绕过吗？ | 能（`r''m -rf`、变量拼接）。它的定位是拦手滑，不是对抗攻击。生产要上容器 |
| `auto-approve` 会跨轮泄漏吗？ | 不会，每轮 `_run_turn` 重置 |

### 关于扩展

| 问题 | 答题方向 |
|---|---|
| MCP 握手流程？ | `initialize` → `notifications/initialized` → `tools/list` → `tools/call` |
| 为什么 JSON-RPC 要加锁？ | 一问一答模型，并发写 stdin 会响应错配 |
| Server 往 stdout 打日志怎么办？ | 每行先试 `json.loads`，解析失败就跳过，不报错 |
| 一个 MCP Server 挂了会怎样？ | 记进 `errors`，启动继续，`/mcp` 可见 |
| 怎么判断 MCP 工具能不能免确认？ | 认 `annotations.readOnlyHint`，没声明的一律按不可逆处理 |
| 工具和技能怎么选？ | 有确定输入输出、需要权限检查 → 工具；方法论、输出格式约定 → 技能 |
| 技能索引里为什么写"不要凭技能名猜测内容"？ | 不写这句模型会看到名字就凭想象执行，而不是先加载 |

### 关于测试

| 问题 | 答题方向 |
|---|---|
| 不联网怎么测 Agent？ | `Provider` 抽象换 `ScriptedProvider`，按剧本返回响应 |
| 枚举了哪些关键场景？ | 收敛、步数上限、熔断、危险命令拦截、非法 JSON 自愈、折叠、丢弃、索引模式、配置合并 |
| 测出过什么真 bug？ | 四个：`Path("")` 真值短路、丢弃只丢一轮、安全下限顶掉预期、绕过注册路径 |

## 讲述时的三个禁忌

1. **不要背文档。** 面试官会往细节里追，背下来的东西一追就散。
   挑 2~3 个你真的想明白了的点讲透，比铺满十个点更有说服力。

2. **不要说"我参考了 XX 项目的架构"就完了。**
   要能说出**你为什么这么选**、**对比方案是什么**、**代价是什么**。
   例如"我没用 LangGraph，因为核心链路不到 200 行，
   框架会把关键细节藏起来，而这个项目的目的是把细节讲清楚"。

3. **不要回避"不完美"。** 主动说局限反而加分：
   "黑名单是正则匹配，可以绕过，它的定位是拦手滑而不是对抗攻击，
   生产环境应该上容器隔离和只读挂载。"
   ——这显示你知道边界在哪。

## 如果被问到"这和 Claude Code / 其他 coding agent 有什么关系"

诚实回答。参考公开产品与开源项目的设计思路是正常的工程实践，
关键是**你自己做了什么、为什么这么做**：

> 架构上我参考了公开的 coding agent 设计思路——比如工具按需暴露、
> 权限分级、Skills 按需加载，这些是公开讨论中的共识做法。
> 但具体实现都是我自己写的：手写 JSON-RPC 客户端、
> 两级上下文裁剪策略、可逆性驱动的权限模型、
> 以及那四个踩坑记录。我能解释每一行代码为什么这么写。

这个回答既诚实，又正好把话题引向你的强项。
