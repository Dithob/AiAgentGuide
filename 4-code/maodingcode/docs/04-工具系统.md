# 04 · 工具系统

代码：`maodingcode/tools/base.py`、`registry.py`、`builtin.py`

## 工具的五个字段

```python
@dataclass
class Tool:
    name: str                    # 唯一标识，模型按名字调用
    description: str             # 决定模型"什么时候想起用它"
    parameters: dict             # JSON Schema，决定参数能不能写对
    handler: Callable            # 真正的执行逻辑
    read_only: bool = False      # 只读工具可直接跑，写类工具走权限确认
    reversibility: Reversibility # 可逆性分级
    source: str = "builtin"      # builtin / mcp:<name> / skill:<name>
```

`description` 是**最重要**的字段。它决定了模型的工具选择准确率。

本项目的工具描述统一写成两段式：

```
读取工作区中某个文本文件的内容，带行号。          ← 是什么
什么时候用：需要修改某个文件之前、需要确认实现细节时。 ← 什么时候用
注意：大文件请配合 offset/limit 分段读。           ← 边界
```

只写第一段，模型容易在"该不该用"上判断失误——比如用 `read_file` 去查目录。

## 内置工具清单

| 工具 | 类型 | 可逆性 | 说明 |
|---|---|---|---|
| `read_file` | 只读 | read_only | 带行号，支持 offset/limit 分段 |
| `write_file` | 写入 | reversible | 整体覆盖，用于新建 |
| `edit_file` | 写入 | reversible | 精确字符串替换，要求唯一匹配 |
| `list_dir` | 只读 | read_only | 目录在前文件在后，带大小 |
| `glob_files` | 只读 | read_only | 按文件名模式查找 |
| `grep_files` | 只读 | read_only | 正则搜内容，返回 文件:行号:内容 |
| `run_shell` | 写入 | irreversible | 执行命令，走黑名单 + 确认 |
| `todo_write` | 只读 | read_only | 多步任务的显式清单 |
| `remember` | 写入 | reversible | 追加跨会话结论到 MAODING.md |

## 三个设计决策

### 1. edit_file 用字符串替换，不用行号

```
❌ replace_lines(path, 10, 15, new_content)     # 模型数错行就改错地方
✅ edit_file(path, old_string, new_string)      # 找不到就不改
```

`old_string` 必须唯一，否则拒绝执行并提示"请扩大上下文让它唯一"。
宁可让模型多一轮，也不要静默改错位置——后者用户很难发现。

### 2. 工具结果永远返回字符串

见 `02-Agent-Loop引擎.md` 的说明。核心是避免中文被序列化成转义序列。

### 3. 错误信息要"可自愈"

对比两种文件不存在的返回：

```
❌ FileNotFoundError: utils.py
✅ 文件不存在：utils.py
   /workspace/src 下的文件：main.py, config.py, agent.py, utils_old.py
```

第二种多花几十个 token，但模型下一轮直接把路径改成 `src/utils_old.py` 就成功了。
省掉的是**一整轮往返**（一次模型调用 = 几千 token + 几秒延迟）。

同样的思路用在 `edit_file` 上：匹配失败时不止说"没找到"，
还提示"文件共 N 行，建议先 read_file 确认"。

## 注册中心

```python
registry = ToolRegistry(policy=policy)
registry.register_all(build_builtin_tools(workspace))
registry.schemas()                      # → 发给模型的 schema 列表
registry.dispatch("read_file", {...})   # → 执行
```

`register()` 有个副作用：调用 `policy.register_reversibility()` 把工具的可逆性
回填给权限策略。这样"工具是什么性质"只在一个地方声明（工具定义里），
策略层不需要维护第二份表——两份表迟早会不一致。

## 索引模式：工具太多怎么办

内置工具 + 3 个 MCP Server + 20 个技能，工具数轻松破 50。
把所有 schema 一次性发给模型有三个问题：

1. **占上下文**：每个 schema 平均 100~200 token，50 个就是 1 万 token，**每轮都发**；
2. **降准确率**：候选工具越多，选错概率越高；
3. **贵**：缓存命中率也会下降。

所以 `schemas()` 在工具数超过 `index_mode_threshold`（默认 40）时自动退化：

```python
# 直接模式：全部工具 schema
[read_file, write_file, edit_file, ...]

# 索引模式：只给两个元工具
[list_tools(keyword), call_tool(tool, arguments)]
```

模型先用 `list_tools("read")` 检索，再用 `call_tool` 调用。
`dispatch()` 里做一层转发，对上层完全透明。

**这个开关不需要改任何业务代码**，加工具加到一个阈值就自动生效。

## 参数校验

`validate_args()` 只查两件事：必填项、类型。

不做完整 JSON Schema 校验是刻意的：模糊的 schema 错误（"参数 a 应为 array"）
直接回灌给模型，它下一轮就能改对。在本地拦得太严反而多一轮无用往返。

校验失败时的返回格式：

```
参数错误：参数 limit 类型应为 integer，实际收到 str
期望的 schema：{path*:string, offset:integer, limit:integer}
```

## 加一个新工具

```python
# tools/builtin.py

@tool(
    name="count_lines",
    description=(
        "统计文件行数。\n"
        "什么时候用：需要快速判断文件规模、决定是否分段读取时。"
    ),
    parameters={
        "type": "object",
        "properties": {"path": {"type": "string", "description": "文件路径"}},
        "required": ["path"],
    },
    read_only=True,
    reversibility=Reversibility.READ_ONLY,
)
def count_lines(path: str) -> str:
    p = _resolve(path)
    if not p.is_file():
        return f"文件不存在：{path}\n{_sibling_hint(p)}"
    return f"{path} 共 {len(p.read_text(encoding='utf-8').splitlines())} 行"
```

然后在 `build_builtin_tools()` 的返回列表里加上它。
可逆性会被自动回填给策略层，不需要改 `policy.py`。
