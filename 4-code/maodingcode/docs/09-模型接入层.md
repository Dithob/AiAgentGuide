# 09 · 模型接入层

代码：`maodingcode/provider/`

## 一个窄接口

```python
class Provider(ABC):
    def chat(self, messages, tools) -> ChatResponse: ...
    def count_tokens(self, text) -> int: ...
```

`AgentLoop` 只知道 `ChatResponse`（含 `content` / `tool_calls` / `usage`），
不知道你用的是哪家模型。**换模型 = 换一个 Provider 实例，Loop 一行都不用改。**

## 为什么只做一个 OpenAI 兼容适配器

市面上绝大多数服务都提供 `/chat/completions` 接口：DeepSeek、智谱、通义、
火山引擎、Kimi、Ollama、vLLM、LM Studio……

所以一个适配器就覆盖一大片。分工是：

```
provider/
├── base.py            Provider 抽象 + ChatResponse / ToolCallRequest / Usage
└── openai_compat.py   OpenAI 兼容实现
```

以后要接 Anthropic 原生协议，就在 `build_provider()` 里分流：

```python
def build_provider(cfg) -> Provider:
    if cfg.name == "anthropic":
        return AnthropicProvider(cfg)
    return OpenAICompatProvider(cfg)
```

## 为什么不引入官方 SDK

`openai_compat.py` 用 `urllib` 手写 HTTP 请求。这是个有代价的选择：

| | 手写 urllib | 官方 SDK |
|---|---|---|
| 依赖 | 零 | 一个包 + 它的依赖树 |
| 升级风险 | 无 | 大版本升级可能破坏接口 |
| 可控性 | 完全知道发了什么 | 需要翻源码 |
| 流式支持 | 要自己解析 SSE | 现成 |
| 重试/超时 | 自己实现 | 现成 |

在**这个项目**里选手写的理由：控制依赖数量是第一优先级（要能在任何装了
Python 3.11 的机器上跑），而且核心链路短，自己写反而更容易讲清楚。

如果要做生产级的流式输出，换 SDK 更划算——`_request()` 换掉即可，上层无感。

## 请求构造

```python
payload = {
    "model": cfg.model,
    "messages": messages,
    "temperature": cfg.temperature,
    "max_tokens": cfg.max_tokens,
    "stream": False,
}
if tool_list:
    payload["tools"] = tool_list
    payload["tool_choice"] = "auto"
```

`temperature` 默认 `0.2` 而不是 `0.7`：编码任务要的是稳定和确定性，
调到 `0.7` 会出现同一个问题每次给的改法都不一样。

有工具时才带 `tools` 字段——**空数组和字段缺失不是一回事**，
部分服务收到 `tools: []` 会直接报错。

## 重试策略

```python
RETRYABLE_STATUS = {408, 409, 429, 500, 502, 503, 504}

def _request_with_retry(self, payload, attempts=3):
    for i in range(attempts):
        try:
            return self._request(payload)
        except ProviderError as exc:
            if not exc.retryable or i == attempts - 1:
                raise
            time.sleep(0.5 * (2 ** i))   # 0.5s → 1s → 2s
```

关键设计：**区分可重试与不可重试**。

| 情况 | 可重试 | 原因 |
|---|---|---|
| 429 限流 | ✅ | 等一下就好了 |
| 5xx 服务端错误 | ✅ | 通常是暂时的 |
| 网络不可达 / 超时 | ✅ | 抖动 |
| 401 鉴权失败 | ❌ | Key 错了，重试一百次也没用 |
| 400 参数错误 | ❌ | 请求本身有问题 |
| 响应不是合法 JSON | ❌ | 服务端问题，但重试没用 |

不可重试的错误立刻抛出，避免用户等三次退避还是一样的错误。

## 响应解析的三个坑

### 1. content 可能是 null

触发工具调用时，`message.content` 通常是 `null`，不是空串。
直接 `.strip()` 会 `AttributeError`。

```python
content = msg.get("content") or ""
```

### 2. content 可能是数组

部分服务（多模态）返回分段内容：

```python
if isinstance(content, list):
    content = "".join(part.get("text", "") for part in content if isinstance(part, dict))
```

### 3. 工具参数可能不是合法 JSON

模型偶尔会输出语法错误的 JSON（缺引号、多逗号）。
不能抛异常中断——**保留原文，转成可自愈的提示回灌**：

```python
try:
    args = json.loads(raw_args)
    parsed_ok = True
except json.JSONDecodeError:
    args, parsed_ok = {}, False          # 保留 raw_arguments
```

`Loop._execute_one()` 拿到 `raw_arguments` 非空时，会返回：

```
参数不是合法 JSON，请重新发起调用并输出合法 JSON。收到的原文：{path: "a.txt"}
```

模型下一轮基本都能改对。

### 4. 缓存 token 的字段名不统一

```python
cached = int(
    raw.get("prompt_cache_hit_tokens")                          # DeepSeek
    or (raw.get("prompt_tokens_details") or {}).get("cached_tokens")  # OpenAI
    or 0
)
```

缓存命中率直接影响成本，值得兼容多家字段名。

## token 计数

```python
def count_tokens(self, text: str) -> int:
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    other = len(text) - cjk
    return cjk + max(1, other // 4)
```

中文约 1 字 1 token，英文约 4 字符 1 token。

**不引 tiktoken 的理由**：上下文裁剪只需要"量级正确"——
判断 12000 还是 120000 token，粗估完全够用。
引入 tiktoken 会带进来一个二进制依赖（不同平台还要编译），
让项目在别人机器上跑起来的成本上升。

代价要说清楚：**这个估算是偏高的**（实际 token 通常比估算少 10~20%），
所以裁剪会稍微保守一点。对安全性有利，对成本略微不利。可以接受。

## 支持的配置方式

```bash
# .env / 环境变量
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=sk-xxx
AI_MODEL_NAME=deepseek-chat

# 也认 MOD_ 前缀（MOD_API_KEY / MOD_BASE_URL / ...）
```

```toml
# maodingcode.toml
[model]
name = "deepseek-chat"
context_window = 128000
price_in_per_1k = 0.002
price_out_per_1k = 0.008
```

```bash
# 命令行覆盖（单次调试；注意在 4-code/ 目录下执行，它是 maodingcode 包的导入根）
python -m maodingcode -m deepseek-reasoner --base-url https://api.deepseek.com/v1
```

优先级：默认值 < 环境变量 < `maodingcode.toml` < 命令行参数。
