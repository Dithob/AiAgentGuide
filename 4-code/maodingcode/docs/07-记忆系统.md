# 07 · 记忆系统

代码：`maodingcode/core/memory.py`

## 记忆要分两层看

混在一起讲容易翻车。这个项目把它拆成两层：

| | 长期记忆 | 短期记忆 |
|---|---|---|
| 载体 | `MAODING.md` | 对话历史 + 会话快照 |
| 生命周期 | 跨会话 | 会话内 |
| 谁维护 | 用户手写，Agent 也可追加 | 框架自动管理 |
| 去哪了 | 注入系统提示 | 参与上下文裁剪 |

## 长期记忆：MAODING.md

放在工作区根目录，每次会话都读进系统提示。

```markdown
# MAODING.md

## 项目概览
- 这个项目是做什么的：
- 技术栈：Python 3.11 + 标准库
- 代码在哪个目录：maodingcode/

## 构建与测试
python tests/smoke_test.py

## 约定
- 提交信息格式：<type>: <summary>

## 已知坑
- asyncio 在这台机器上需要手动设置事件循环策略
```

设计要点：

**只放"每次都要知道"的东西。** 它每轮都发，越长越贵。
经验值是控制在 100 行以内。

**只追加、不重写。** `append_note()` 用 `open("a")` 追加：

```python
### [2026-09-19 16:52] 构建命令

测试前必须先跑 lint
```

为什么不重写整个文件？因为用户可能已经手工整理过内容，
让模型重写等于有概率把人工整理的成果覆盖掉。追加是幂等安全的。

**超过 8000 字符就截断**（`MAX_MEMORY_CHARS`），并明确提示"内容过长已截断"。
截断而不是报错，是因为记忆过长是常见情况，不该阻断使用。

## 短期记忆：会话快照

```python
store.save_session("refactor-auth", context.messages)
msgs = store.load_session("refactor-auth")
```

落盘到 `.maodingcode/sessions/<name>.json`，对应 CLI 的 `/save` 和 `/load`。

存的是消息的**结构**而不只是文本：

```json
{
  "saved_at": "2026-09-19 16:52:31",
  "message_count": 14,
  "messages": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "", "tool_calls": [...]},
    {"role": "tool", "tool_call_id": "c1", "name": "read_file", "content": "..."}
  ]
}
```

必须保留 `tool_calls` 和 `tool_call_id`，否则恢复后 `tool_call` / `tool_result`
配对断裂，服务端会拒绝。这也是为什么 `Message` 要显式建模而不是到处传裸 dict。

`/load` 不带参数时恢复最近一次会话（按 mtime 排序），
这个体验细节比想象中重要——用户不想记会话名。

## 为什么不用向量库

这是最常被问到的设计选择。答案是：**检索解决"大"，不解决"准"。**

项目约定是几十到几百行的**结构化文本**，特点是：

- 总量小，全量注入的成本可以接受；
- 每条都可能有约束力（"测试前必须先跑 lint"漏掉就出事）；
- 需要的是完整性，不是相关性。

向量检索会引入两个新问题：召回率不保证（漏掉关键约定）、
以及"检索到的内容与当前问题不相关"带来的干扰。

**什么时候才该上向量库**：记忆量大到无法全量注入（比如整个代码库的文档），
或者需要按语义查找历史对话。那是 `RAG` 那一章的适用场景，
和"项目约定"这个需求不是一回事。

## CLI 用法

```bash
> /memory                 # 查看当前项目约定
> /memory init            # 创建 MAODING.md 模板
> /memory 测试用 pytest    # 追加一条并立即生效
```

`/memory <内容>` 追加后会调用 `_refresh_system_prompt()` 立即刷新系统提示，
不需要重启会话。

模型也可以通过 `remember` 工具自己追加结论——这是"Agent 主动记笔记"的入口。

## 边界

| 该写进 MAODING.md | 不该写进去 |
|---|---|
| 构建/测试命令 | 某次调试的临时路径 |
| 代码风格约定 | 当前任务进度（会被覆盖） |
| 反复踩的坑 | 密钥与个人信息 |
| 目录结构说明 | 大段代码片段 |
