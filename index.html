一、三层分离：每一层只干一件事

把「记」和「整理」混在一起，是学习笔记最大的浪费——边看边精修，既慢又记不住。拆成三层之后，每层目标单一，可以分别优化。

关键纪律

纪律说明
只记你关心的判断标准：面试官问到这个，我答不上来会不会很难看？会 → 记。教程里大段铺垫、多语言重复代码、纯 UI 演示 → 不记。
知识点卡片化每个知识点写成一张 K-xx 卡，而不是一段流水账。卡片才能被检索、复用、跨章合并。
编号永不变跨文件引用一律用编号（见 K-07、衍生自 Q-12），让笔记长成网络而不是孤岛。
选择题只当体检表有选项就是「再认」，难度被稀释。用它定位漏洞，再用开放题训练「讲得出来」。

三、怎么用（每章照做）

  1. 复制模板：0-记录区/_模板-章节记录.md → chXX-标题.md，填头部信息。
  2. 读的过程中只填「📖 正文要点」，不要停下来精修。
  3. 读完立刻做课后选择题，只写「选了哪个 + 一句话解析 + 考点 + 衍生开放题」。
  4. 想到的疑问丢进「❓ 疑问」，不要现场查。
  5. 二次整理：要点按知识点归并进 1-知识库/；选择题去选项化，衍生题写进 2-面试题库/02-开放题-口述版.md。
  6. 复习：30 秒看知识库总表 → 3 分钟出声讲开放题，卡壳就回查卡片。

六、核心方法：选择题 → 开放题 六手法

教程给的是选择题，面试不发选项。拿到任何一道选择题，按下面六种手法依次过一遍，就能榨出 3~6 道真实面试题。

A
去选项化　把「以下哪个是 ×」改成直接提问。
→ 请说明 × 是什么、为什么
B
追问原理　加 Why：为什么这样设计？底层机制是什么？
→ 为什么"前缀完全相同"才能命中缓存？
C
落到工程　加 How：项目里怎么落地？有没有具体配置？
→ 你会怎么设计 Prompt 结构来最大化缓存命中率？
D
加边界权衡　什么时候不适用？代价是什么？
→ 什么情况缓存一定命中不了？这时怎么办？
E
干扰项变陷阱　错误选项通常对应真实误区，做成纠错题。
→ 有人说"流式输出更省钱"，对吗？
F
反向假设　改条件会怎样？
→ 如果缓存的是中间段而不是前缀，设计上有什么不同？

四级深度（面试官真实递进路径）

层级问什么答不上来的含义
L1是什么？硬伤，直接减分
L2为什么？底层怎么做？说明是背的，不是懂的
L3工程上怎么用？怎么落地？说明没有实战，只读过书
L4什么场景不适用？代价是什么？区分「会背」和「能干活」的分水岭
训练目标：每个核心知识点至少能答到 L3；自己最熟的三五个知识点要能答到 L4。 判断标准是——不看任何材料，60 秒把一道 L3 题讲完整，并主动补一句边界。

八、教程勘误登记（已查证）

位置问题判定
§1.1 缓存折扣正文写「缓存单价约 50%」，课后题 Q26 解析写「输入成本降约 90%」。两个数字不是同一口径，已在知识库 02 并列记录，答题前先确认题目问的是哪个。口径冲突
