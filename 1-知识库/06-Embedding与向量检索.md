## 🎯 30 秒结论

1. Embedding 把文本映射成**高维稠密向量**（768~3072 维），语义相近则向量距离近。
2. 三种相似度：**余弦 [-1,1]**（最常用）/ 欧氏距离 [0,+∞) / 点积（最快）。
3. **RAG 不把全文塞进上下文**的三个理由：①超窗口 ②无关信息干扰注意力 ③Token 成本高。
4. 稠密向量管语义，稀疏向量（BM25/TF-IDF）管精确关键词；生产上常做**混合检索**。
5. Embedding 是 Agent 长期记忆与知识检索的地基——没有它，Agent 就没有"外部记忆"。

**Q5: Embedding 的作用是什么？怎么计算语义相似度？**

> Embedding 将文本转换为高维向量（通常 768-3072 维），使语义相近的文本在向量空间中距离也近。它是语义搜索和 RAG 的基础。计算语义相似度最常用的是**余弦相似度**（衡量向量方向一致性，范围 [-1,1]，值越大越相似），此外还有欧氏距离（衡量绝对距离）和点积（同时考虑方向和大小）。在 RAG 系统中，用户问题和文档都经过 Embedding 后，用余弦相似度找到最相关的文档片段。

> ⚠️ **这里是你的错题点**：你在「余弦相似度的值域」上先选了 `~~A~~ [0,1]`，正确答案是 **B [-1,1]**（`~~A~~ B`）。
> **一句话根治**：**余弦只看方向，向量可以完全反向 → 所以下界是 -1，不是 0。** 只有"距离"类指标（欧氏距离）的下界才是 0。
>
> | 指标 | 值域 | 下界为什么是它 |
> | :--- | :--- | :--- |
> | 余弦相似度 | **[-1, 1]** | -1 = 方向完全相反（如 `[1,0]` 与 `[-1,0]`） |
> | 欧氏距离 | [0, +∞) | 距离是非负的，0 = 完全重合 |
> | 点积 | (-∞, +∞) | 同时受方向和模长影响，无界 |

> 你在记录区还摘录了**稠密/稀疏向量**段落和**三种相似度的 Python 实现代码**——本文「二、稠密向量 vs 稀疏向量」「三、向量相似度计算」是它的整理版。

## 一、Embedding 是什么

| 项 | 说明 |
| :--- | :--- |
| 定义 | 把文本转换成一个高维浮点向量，使语义相近的文本向量也相近 |
| 维度 | 通常 768 ~ 3072 维 |
| 直觉 | 想象一个多维空间：x=动物性、y=体型、z=可爱度 → "猫"和"狗"近，"猫"和"汽车"远 |
| 特点 | 每一维的含义是模型自动学出来的，人类无法直接解读 |
| 用途 | 语义搜索（RAG 的基础）、推荐、聚类、去重、长期记忆检索 |

**核心用途链条**

```
知识库文档 → Embedding → 存入向量数据库
用户提问   → Embedding → 向量检索找最相似的片段 → 注入上下文 → LLM 生成答案
```

---

## 二、稠密向量 vs 稀疏向量

| 维度 | 稠密向量 Dense | 稀疏向量 Sparse |
| :--- | :--- | :--- |
| 取值 | 每一维几乎都有非零值 | 绝大多数维为 0，少数维有值 |
| 代表 | 现代 Embedding 模型 | BM25 / TF-IDF |
| 擅长 | **语义相似**（"猫" ≈ "小猫咪"） | **精确关键词**（函数名、SKU、法条编号） |
| 弱点 | 可能漏掉专有名词 / 编号 | 不理解同义与语义泛化 |

> 生产实践：**混合检索（Hybrid Search）** —— 稠密 + 稀疏各自召回，再用 Rerank 重排。

## 三、向量相似度计算（考点密集）

| 方法 | 公式 | 值域 | 特点 |
| :--- | :--- | :--- | :--- |
| **余弦相似度** | `a·b / (‖a‖‖b‖)` | **[-1, 1]** | 只看方向、忽略长度，**最常用**；对文本长短不敏感 |
| 欧氏距离 | `‖a - b‖` | [0, +∞) | 衡量空间绝对距离，**对向量大小敏感** |
| 点积 | `a · b` | (-∞, +∞) | 方向 + 大小同时考虑，**计算最快** |

**余弦相似度取值含义**

| 值 | 含义 |
| :--- | :--- |
| 1 | 方向完全相同（语义最相似） |
| 0 | 正交（语义无关） |
| -1 | 方向相反 |

> 若先把向量**归一化**（单位化），点积 = 余弦相似度 → 既快又等价。这是工程上常见做法。

## 五、RAG 为什么不直接塞全文（高频）

| 理由 | 说明 |
| :--- | :--- |
| ① 超窗口 | 全文可能直接超出上下文窗口限制 |
| ② 注意力干扰 | 大量无关信息会稀释注意力，**回答质量反而下降** |
| ③ 成本 | 全文输入 Token 消耗巨大，费用高昂、延迟升高 |

→ 先 Embedding 检索出**最相关的片段**再注入，兼顾**准确性 / 速度 / 成本**三者的平衡。

---

## ⚠️ 易错点

| 常见错误说法 | 正解 |
| :--- | :--- |
| 余弦相似度值域是 [0, 1] | 是 **[-1, 1]**（[0,+∞) 是欧氏距离） |
| Embedding 的主要目的是压缩文本省存储 | 目的是**语义表示**，压缩只是副产品 |
| 稠密向量可以完全取代 BM25 | 精确关键词（编号、专有名词）场景仍需稀疏检索 |
| 维度越高一定越好 | 精度提升有限，但存储与计算成本线性上升 |
| 检索到就能答对 | 检索质量决定上限，还需 Chunk 切分与 Rerank |

## 🎤 面试怎么答（口述模板）

> **问：Embedding 的作用是什么？怎么算语义相似度？**
> "Embedding 把文本映射成高维稠密向量，通常是 768 到 3072 维，让语义相近的文本在向量空间里距离也近。算相似度最常用余弦相似度，值域是 -1 到 1，只看方向不看长度，所以对文本长短不敏感；另外还有欧氏距离和点积，点积最快，如果先把向量归一化，点积和余弦就等价了。"

> **追问：为什么 RAG 不直接把全文塞进上下文？**
> "三个原因。一是全文可能超上下文窗口；二是塞进去大量无关信息会稀释注意力，模型反而答得差，中间的信息还容易丢；三是 Token 成本高、延迟大。所以先用 Embedding 检索出最相关的几个片段再注入，在准确性、速度和成本之间取平衡。"
