## ⚡ TL;DR（先看这三行，下面正文是参考资料）

- **一句话**：Agent 与 ChatBot 的差异**不在模型，在架构**——外挂了工具层 + 记忆层 + 循环控制层。
- **三要点**：①四大能力域（感知/思考/行动/观察）构成闭环，**缺任一个都会退化**；②三次进化是纯聊天 → +工具 → +循环+记忆，"能调 API" ≠ "会规划"；③**有明确适用边界**——确定性高、流程固定的任务用传统程序更划算。
- **追问**：四个能力域里如果缺了"观察"，Agent 会退化成什么？（→ [O-01](../2-面试题库/开放题/01-Agent全景与能力框架.md)）

---

## 🎯 30 秒结论

1. Agent 与 ChatBot 的差异**不在模型，在架构**：Agent 外挂了工具层 + 记忆层 + 循环控制层。
2. 四大能力域（感知 / 思考 / 行动 / 观察）构成闭环，**缺任何一个都会退化**。
3. 三次进化：纯聊天 → +工具 → +循环+记忆。第二代"能调 API" ≠ "会规划"。
4. Agent **有明确的适用边界**：确定性高、流程固定的任务，用传统程序更划算。

---

## 一、Agent ≠ 更聪明的 ChatBot

| 对比维度 | 普通 ChatBot | AI Agent |
| :--- | :--- | :--- |
| 回答方式 | 基于训练数据直接回答 | 判断是否需要工具，主动调用取实时数据 |
| 数据来源 | 只用训练时的历史数据 | API / 网页搜索 / 数据库 |
| 思考过程 | 一次生成，无中间步骤 | Thought → Action → Observation 循环 |
| 纠错能力 | 无法自我纠错 | 观察结果后重新决策，自动纠错 |
| 记忆能力 | 仅当前对话上下文 | 短期 + 长期记忆，跨会话保持 |

**一句话本质**：两者用的是**同一个底层 LLM**，Agent 多出来的是**外围架构**（工具、记忆、循环、权限）。

---

## 二、四大能力域与核心闭环

| 能力域 | 运行时概念 | 职责 |
| :--- | :--- | :--- |
| 👁️ **感知 Perceive** | Input / Context | 接收用户输入、环境信号、工具返回结果、多模态输入 |
| 🧠 **思考 Think** | Reasoning / Planning | 推理、任务拆解、规划下一步、记忆检索 |
| ⚡ **行动 Act** | Tool Use / Action | 调 API、执行代码、操作浏览器、多 Agent 协作 |
| 👀 **观察 Observe** | Observation / Tool Result | 解析执行结果、评估效果、反思纠错 |

```
   感知 ──▶ 思考 ──▶ 行动 ──▶ 观察
     ▲                            │
     └──────── 再思考 ◀───────────┘
        （循环直到任务完成或触发终止条件）
```

**为什么"观察"是灵魂**：只有观察让 Agent 看到自己行动的后果，才有纠错。没有观察环节，循环就退化成"连问几次"，不会变聪明。

## 三、三次进化

| 能力维度 | 第一代 💬 ChatOnly | 第二代 🔧 Tool-Enabled | 第三代 🤖 ReAct Agent |
| :--- | :--- | :--- | :--- |
| 时间 | 2022-2023 | 2023-2024 | 2024-2026 |
| 代表 | ChatGPT 早期 | Function Calling | ReAct Agent / Devin / Computer Use |
| 对话能力 | ✅ 基础 | ✅ 基础 | ✅ 基础 |
| 工具调用 | ❌ 不能 | ✅ 单步 | ✅ 多步循环 |
| 自主规划 | ❌ 不能 | ❌ 一问一答 | ✅ 自动拆解多步任务 |
| 自我纠错 | ❌ 不能 | ❌ 不能 | ✅ 观察后调整策略 |
| 持续记忆 | ❌ 仅当前对话 | ❌ 仅当前对话 | ✅ 短期 + 长期 |
| 实时数据 | ❌ 只有训练数据 | ✅ 可调 API | ✅ 多 API 协同 |

**关键分界**：第二代的"能调 API"是**用户指哪打哪**；第三代才具备**自主拆解任务 + 循环决策**。

---

## 四、Agent 的适用边界

**该用 Agent**：需要调外部工具、需要多步决策、需要持续反馈纠错的不确定任务。

**不该用 Agent**：确定性高、流程固定的任务——用传统程序更快、更便宜、更可靠。

> 判断四问：①流程能否被枚举完？②失败代价有多大？③延迟容忍度？④是否依赖外部实时数据？
> 四问里出现"不能枚举 / 需要外部数据"，才考虑 Agent。

---

## ⚠️ 易错点

| 常见错误说法 | 正解 |
| :--- | :--- |
| Agent 用了更大的模型 | 用的是同一个 LLM，差在架构 |
| Agent 和 ChatBot 本质相同，只是叫法不同 | 架构差异是范式级差异 |
| 智能客服自动回复常见问题 = Agent | 固定问答库是 ChatBot；要调工具查订单才是 Agent |
| 能力域是四个独立模块 | 是闭环上的四个环节，必须协同 |
| 三代里第二代"会规划" | 第二代没有规划，只有单步调用 |

## 🎤 面试怎么答（口述模板）

> **问：Agent 和 ChatBot 有什么区别？**
> "差异不在模型，在架构。ChatBot 是基于训练数据的一问一答；Agent 在 LLM 外面加了三层——工具层（Function Calling）、记忆层（短期+长期）、循环控制层。它跑的是'感知→思考→行动→观察→再思考'的闭环，所以能自主拆解任务、调用工具、根据结果纠错。简单说：ChatBot 只会说，Agent 会想、会做、会改。"

> **追问：那 Agent 什么时候不该用？**
> "确定性高、流程固定的任务不该用。Agent 每个决策点都是一次 LLM 调用，成本和延迟都不低，而且有不确定性。我会先看流程能不能枚举完、失败代价多大——能枚举完就用工作流引擎。"
