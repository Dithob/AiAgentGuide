# 12 · 操作可逆性与授权范围

> **来源**：ch02 §2.5b　|　**整理**：2026-09-13　|　**最后核对**：2026-09-13
> **标签**：#权限 #安全 #工程实践 #面试加分　|　**关联**：07（工具是"动作"）

---

## 🎯 30 秒结论

1. 闭环里的"行动"在教学中被简化成"调用工具"，但工业级 Agent 必须先回答：**哪些能自由执行，哪些要用户确认？**
2. 判据不是"危险等级"，而是**可不可逆**——**可逆性比安全性更实用**。
3. 三级：**可逆 → 自由执行**；**不可逆 → 需确认**；**危险 → 始终确认且不可跳过**。
4. **单次授权 ≠ 全局授权**：批准"删除 dist/"不等于批准"删除任意目录" → 防**授权蔓延**。
5. 这是**面试加分点**：能说出可逆性分级 + 授权范围原则，说明你理解工业级 Agent 设计。

---

## 一、三级可逆性（源自 Claude Code 的真实设计）

| 级别 | 定义 | 执行策略 | 示例 |
| :--- | :--- | :--- | :--- |
| **可逆操作** | 可撤销 / 回滚 / 自动修复 | ✅ **自由执行，不需确认** | 读文件、搜索代码、运行测试、创建临时文件 |
| **不可逆操作** | 无法撤销，或恢复代价极高 | ⚠️ **需用户确认** | 删除文件、`git push`、发邮件、改配置 |
| **危险操作** | 影响系统安全 / 不可控后果 | 🚫 **始终需确认，不可跳过** | `rm -rf /`、`git push --force`、改 `settings.json` |

---

## 二、为什么"可逆性"比"安全性"更实用

传统安全模型按**危险等级**（低/中/高危）分级。但在 Agent 场景里，这个标准会得出反直觉的结论：

| 操作 | 按"危险等级"看 | 按"可逆性"看 | 结论差异 |
| :--- | :--- | :--- | :--- |
| 运行测试 | 安全 → 自由执行 | **可逆**（失败重跑即可） | 一致 |
| 修改文件 | 中危 → 需确认 | **可逆**（有 Git 可回滚） | **可逆性建议放行** |
| 发送邮件 | 安全 → 放行 | **不可逆**（发出去收不回） | **可逆性要求确认** ⚠️ |
| 删除文件 | 中危 | 不可逆 | **可逆性要求确认** |

> 核心洞察：**"能不能撤销"比"危不危险"更能决定该不该拦。** 发邮件按传统分级是"安全的"，但它恰恰最需要确认。

---

## 三、授权范围原则：单次授权 ≠ 全局授权

**原则**：用户对某次操作的授权，**仅限于该次执行、该操作对象、该操作类型**。不能以此为依据自动执行同类操作。

**它解决什么问题**：**授权蔓延**——Agent 拿到一次"删除文件"的许可后，开始自动删别的文件，超出用户预期。

**实现要点**

| 要点 | 说明 |
| :--- | :--- |
| ① 每次不可逆操作前**重新请求确认** | 不复用上一次的"允许" |
| ② 确认信息**包含具体对象** | 说"删除 `dist/build.js`"，而不是"删除文件" |
| ③ 危险操作的确认**不可"不再提示"** | 不提供"记住选择"的选项 |
| ④ `deny` 对该次请求**粘性生效** | 不能重试一下就变成 `allow` |

> 这与第 1 章学的 **权限三态 `allow / deny / ask`** 是同一套思想：
> **"会做"和"可以做"必须分开**，而且授权不能被继承、放大、或悄悄升级。

---

## ⚠️ 易错点

| 常见错误说法 | 正解 |
| :--- | :--- |
| 按危险等级分级就够了 | 可逆性更实用——它抓住了"能不能挽回"这个本质 |
| 安全操作可以直接放行 | "安全但不可逆"（发邮件）恰恰必须确认 |
| 用户批准过一次，同类操作就不用再问 | **单次授权 ≠ 全局授权**，这是授权蔓延的入口 |
| 确认框写"是否删除文件？"就行 | 必须写具体对象（哪个文件），否则用户无法做有效判断 |
| 危险操作可以勾选"不再提示" | 不行，危险操作的确认不可跳过 |

---

## 🎤 面试怎么答（口述模板）

> **问：Agent 怎么安全地执行操作？**
> "我会按**可逆性**而不是危险等级来分级，因为 Agent 场景下'能不能撤销'才是实用判据。第一类是**可逆操作**，比如读文件、搜代码、跑测试，失败了重来就行，自由执行；第二类是**不可逆操作**，比如删文件、git push、发邮件，必须用户确认——注意发邮件按传统分级是'安全的'，但它发出去收不回来，所以照样要拦；第三类是**危险操作**，比如 rm -rf /、force push，始终确认且不能跳过。
> 另外有一条更重要的原则：**单次授权 ≠ 全局授权**。用户批准'删除 dist/'，不等于批准'删除任意目录'，每次不可逆操作都要独立确认，确认信息里要写清具体对象。这条是为了防止**授权蔓延**。"
