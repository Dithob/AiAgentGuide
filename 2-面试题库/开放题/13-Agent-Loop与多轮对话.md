### O-27｜Agent 循环什么时候停？怎么防止死循环？

- **级别**：L3　**来源**：ch03 八股 Q3　**条目**：13

**参考回答**

> **主出口是 AI 自己不再请求 `tool_calls`**——它认为信息够了，就返回最终回答，循环结束。但光靠这个不安全，模型可能反复调工具不回头，所以要三层保护：**AI 自主停**（主出口）+ **`max_loops` 上限**（保险丝）+ **超时 / token 预算**（成本熔断）。
>
> 另外要说清**两层循环**：外层 `while True` 是多轮对话（等用户输入，用户说 quit 退出），内层 `while True` 才是单个任务的 Agent 循环。问"循环什么时候停"问的是内层。

**追问链**

1. → 怎么判断 Agent 陷入了循环？（重复动作检测——同样工具、同样参数反复调用）
2. → 超出 `max_loops` 了该怎么收场？（优雅降级，把已拿到的信息和失败原因告诉用户，而不是静默丢弃）

**雷区**

- ❌ 说"循环执行固定次数后停止"
- ❌ 把"用户说 quit"当成 Agent 循环的终止条件

### O-30｜为什么用户追问时 Agent 可以不调工具？

- **级别**：L3　**来源**：ch02-3　**条目**：13

**参考回答**

> 因为 `messages` 是**跨用户输入累积**的——Agent 的记忆就是对话历史。
> 用户先问了"北京天气"、再问"上海天气"，这两个结果都已经在历史里了，第三句"哪个更热"根本不需要再调工具，模型直接从历史里比较 25°C 和 28°C 就行。
>
> 这也暴露了短期记忆的朴素实现：**历史即记忆**。它的代价是历史会无限膨胀——这正是 token 递增的根源（O-28），也是第 7 章记忆系统要解决的问题：摘要、按需召回、长期记忆分离。

**追问链**

1. → 历史无限膨胀怎么办？（摘要压缩 + 向量召回 + 裁剪时保留 system）
2. → 那什么时候应该强制重新调工具？（数据有时效性时——天气、股价这类必须重查）

**雷区**

- ❌ 说"每次追问都要重新调用工具"
