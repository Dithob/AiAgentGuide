### O-01｜从架构角度说明 Agent 比 ChatBot 多了什么

- **级别**：L3　**来源**：Q(ch01-1) 衍生（手法 A+C）　**卡片**：K-01, K-02

**参考回答**

> 差异不在模型，在架构。ChatBot 就是 `prompt → LLM → 文本`，一问一答。Agent 在 LLM 外面加了三层：
> ①**工具层**——通过 Function Calling 把 LLM 的决策落到真实动作（查 API、跑代码、读文件）；
> ②**记忆层**——短期记忆维持当前任务的上下文，长期记忆用向量库跨会话积累；
> ③**循环控制层**——把一次调用变成"感知→思考→行动→观察→再思考"的闭环，直到任务完成或触发终止条件。
> 再往外还有权限层和沙箱，因为工具是"动作"，会碰真实世界。
> 所以 ChatBot 是"会说"，Agent 是"会想、会做、会改"。

**追问链**

1. → 那这四层里，哪一层去掉影响最大？（循环控制层——去掉就退化成第二代的单步工具调用）
2. → 权限层为什么是必需的？（模型理解意图 ≠ 获得授权；高风险操作要人在环）
3. → 这三层在工程上分别落到哪些具体技术？（工具层→Function Calling/MCP；记忆层→向量库+摘要压缩；循环层→Agent Loop 引擎）

**雷区**

- ❌ 说"Agent 用了更大的模型"——底层是同一个 LLM
- ❌ 只说"Agent 会调工具"——漏掉循环和记忆，那是第二代

### O-13｜一个需求该不该上 Agent？怎么判断？（L4）

- **级别**：L4　**来源**：Q-05 衍生（手法 C+D）　**卡片**：K-04

**参考回答**

> 我会问五个问题，任何一个是否定就先别上 Agent。
> ①**流程能不能被枚举完？** 能被枚举完的，用工作流引擎/状态机更快更稳更便宜。Agent 的价值恰恰在"路径不确定"。
> ②**是否需要外部实时数据或工具？** 需要工具才有上 Agent 的理由；纯文本问答用普通 LLM 调用就够。
> ③**失败代价有多大？** 代价高就必须配人工审核或权限分级，那架构复杂度会完全不同。
> ④**延迟和成本容忍度如何？** Agent 每个决策点都是一次 LLM 调用，多轮下来延迟和费用都不低。
> ⑤**有没有可量化的成功标准？** 没有的话，你连它到底变好还是变坏都判断不了。
>
> 结论模板：如果"流程不可枚举 + 需要工具 + 有可量化的验收标准"，那就上 Agent；否则优先做确定性流程，把 LLM 当其中一个环节用。

**追问链**

1. → 那"智能客服"算不算 Agent？（固定问答库不算；如果它要调工具查订单状态、发起退款，那就是 Agent）
2. → 上了之后怎么验证值不值？（建评估集，对比 Agent 方案和固定流程的任务成功率、平均成本、P95 延迟）

**雷区**

- ❌ 把"用了 LLM"等同于"用了 Agent"
