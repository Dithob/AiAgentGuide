### O-41｜Loop / Runtime / Sandbox 三者的关系和职责边界是什么？

- **级别**：L3　**来源**：ch09 八股 Q5（手法 A+B）　**条目**：22

**参考回答**

> **严格嵌套，不是并列**：**Sandbox 在最外层**（所有 Agent 行为最终都在某个隔离环境中执行）→ **Runtime 在中间层**（为 Loop 提供基础设施）→ **Agent Loop 在最内层**（是 Runtime 里的一个逻辑循环）。
> 分工：**Agent Loop 决定"做什么"**（LLM 推理决定下一步行动）；**Runtime 决定"怎么做"**（把逻辑语义转成可执行计算）；**Sandbox 决定"在哪里做、在什么约束下做"**。
>
> **边界问题一句话对应一层**：
> ① "该做什么决策？" → **Agent Loop**
> ② "工具参数合法吗？" → **Runtime 工具注册层**（类型、值域、必填校验）
> ③ "有权限调用吗？" → **Runtime 权限控制层**（角色权限矩阵 + 审批）
> ④ "代码在哪执行？" → **Sandbox**（隔离环境 + 资源限制）
> ⑤ "历史太长怎么办？" → **Runtime 记忆管理层**（窗口压缩 + 摘要替代）
>
> Runtime 自己是五层：LLM 管理 / 工具注册 / 记忆管理 / 执行调度 / 可观测。

**追问链**

1. → Runtime 包括 LLM 推理计算吗？（**不包括**。推理由模型服务端完成，Runtime 只调 API 并处理响应——这是最常见的"不包括"考点）
2. → Agent Loop 是五步还是六步？（教程给的是六步：感知 → 推理 → 规划 → 执行 → 观察 → **评估**。多出的"评估"把"是否结束"从隐式的 `tool_calls` 判断变成显式步骤，**有了评估步才挂得上质量检查**）
3. → 为什么要分这么细？（因为可替换——换 Runtime 不动 Loop，换 Sandbox 不动 Runtime，符合工程上的关注点分离）

**雷区**

- ❌ 说三层是并列的
- ❌ 说 Runtime 负责执行 LLM 推理

### O-42｜Docker 和 Firecracker 做沙箱有什么区别？你怎么选？

- **级别**：L3　**来源**：ch09 八股 Q3 + §9.6（手法 A+D+F）　**条目**：22

**参考回答**

> **核心区别是隔离原理**：**Docker 容器共享宿主机内核**——隔离在进程/文件系统层面，所以**内核漏洞可以逃逸**；**Firecracker 微虚拟机每个沙箱运行独立内核**——内核级隔离，逃逸难度极高。
> **代价对比**：Docker 启动秒级、资源开销小；Firecracker 启动约 **125ms**、资源开销更大（每实例要跑一个内核）。
>
> **选型原则**：**金融 / 医疗这类高安全场景选 Firecracker**；**一般 Web 场景 Docker 够用**；**不想自建就选 E2B / Modal 这类云沙箱**。
> 另外还有两个方向：**进程级**（`subprocess` + `ulimit`/`cgroups`，毫秒级但隔离最弱，只适合简单验证）和 **WASM**（Wasmtime/Wasmer，毫秒级、无系统调用，适合轻量计算）。
>
> **但选完技术还不够——单层沙箱一定不够**，工业级是三层纵深：应用级命令静态分析（23+ 验证器 + AST）→ 权限决策引擎（三步决策 → auto-allow / regular / disabled）→ OS 级隔离（macOS Seatbelt、Linux Bubblewrap + seccomp、Windows PowerShell 包装）。

**追问链**

1. → 单层为什么不够？（静态分析绕不过混淆；权限引擎挡不住 OS 漏洞；OS 隔离挡不住"合法命令的恶意效果"）
2. → 举个"合法命令的恶意效果"的例子？（**裸 Git 仓库的 `core.fsmonitor` 劫持**：攻击者建一个裸仓库并把 `core.fsmonitor` 指向恶意脚本，Agent 执行 `git status` 时 Git 自动跑那个脚本——检查的是无害命令，恶意行为发生在工具内部。防御是进沙箱前 `scrubBareGitRepoFiles()` 清扫）
3. → 沙箱的网络隔离是断网吗？（不是。**HTTP/SOCKS 代理 + 域名白名单**——Agent 能 `npm install`（registry 在白名单），不能 `curl evil.com`。断网最安全但会废掉大部分能力）
4. → 文件系统怎么控？（Bubblewrap 挂载命名空间三级：`--bind` 可写（项目目录、/tmp）、`--ro-bind` 只读（系统库、/usr/bin）、`--dev-null` 完全屏蔽（敏感路径））

**雷区**

- ❌ 说 Docker 和 Firecracker "都是容器，差不多"
- ❌ 说沙箱就是禁用网络
- ❌ 把 `excludedCommands` 当安全边界（原文自己写着"用户便利功能，非安全边界"）
