## 记号系统（记录区 → 我按记号加工）

| 你在记录区写 | 含义 | 我做什么 |
| :-- | :--- | :--- |
| `==……==` | **加强学习标记** | 知识库加「🔆 强化延伸」+ 派生测验题 |
| `~~A~~ B` | 我选 A（错），答案是 B | 面试题库记错题 → 归纳根因 → 写「错题根治」→ 进测验错题池 |
| 正文摘录 / 八股原文 | 你认为重要的原文 | 保真收录进知识库「📌 你的原文记录」，不改写 |
| `> 疑问：……` | 你想到的问题 | 知识库「❓ 你的疑问解答」正面回答 + 配自测题 |

**整理时机**：当天只记不整；一章结束或周末做二次整理。整理的本质是**合并同类项**，不是重抄。

## 每章照做

1. 复制 `0-记录区/_模板-章节记录.md` → `0-记录区/chXX-标题.md`
2. 读的过程中只填「📖 正文要点」
3. 读完立刻做课后选择题：**只用 `~~X~~ Y` 记错题**（我选 X 错，答案是 Y），对的不用抄
4. 疑问用 `> 疑问：……` 写在对应段落旁边，不现场查
5. **标 `==`**：哪些知识点想加强，用 `==……==` 包住标题或关键词
6. 二次整理：原文归并进知识库；高亮项加 🔆 延伸；错题与衍生题进面试题库
7. 做测验：打开 `3-测验/index.html` → 「🔆 强化专项」→ 再「❌ 错题重做」
8. 复习：30 秒看知识库总表 → 3 分钟出声讲开放题

## 题库流水线（改题只需改一个文件）

**核心约定：`3-测验/bank.json` 是题库的唯一编辑入口，`index.html` 是生成产物。**

```
2-面试题库/01-选择题*.md   ← 原始记录（备查，手工同步源）
        │  node tools/export-bank.js
        ▼
3-测验/bank.json           ← ★ 唯一编辑入口（含 id / concept / w）
        │  node tools/build.js
        ▼
3-测验/index.html          ← 生成产物（题库已内联），不要手改题目
```

### 改题流程

```bash
cd AiAgentGuide
node tools/export-bank.js   # ① 从 01-选择题 重新抽取（会覆盖 bank.json）
#    → 手工编辑 3-测验/bank.json（增删改题、调 tag、调 w）
node tools/build.js         # ② 把 bank.json 内联进 index.html
node tools/run-tests.js     # ③ 69 项回归测试
```

一键等价：`npm run sync`（= export → build → test）。

> ⚠️ `export-bank.js` 是**覆盖写**。若已在 `bank.json` 里手工改过题，先备份再导出，或直接手改 `bank.json` 后跳到 ②③。

### bank.json 字段

| 字段 | 含义 | 说明 |
| :--- | :--- | :--- |
| `id` | 稳定标识 `chXX-NN` | 错题池按 id 持久化，**增删题不会串号** |
| `c` | 章节 `ch00`~`ch03` | 组题时按章节统计 |
| `concept` | 知识点标签（已归一化） | 同一组卷内**同 concept 只取一题**（去重开关） |
| `w` | 权重 1~5 | 决定被抽中的概率，见下表 |
| `t` | 题型 `single` / `multi` | |
| `lv` | 深度 L1~L4 | |
| `q` / `o` / `a` / `e` | 题干 / 选项 / 答案 / 解析 | `s` 为强化派生的补充分支（可选） |
| `tag` | 原题标记（`🔆` / `🔁` 等） | 前缀在抽取时已剥离进 `concept` |

### 权重 `w` 推导规则

从「这题是不是重点」推导，累加后**截断到 1~5**：

| 信号 | 加分 |
| :--- | :--- |
| 基础分 | 1 |
| `🔆` 标星（你标记的强化项） | +2 |
| 命中错题池概念（你答错过） | +2 |
| 多选题（本身就更难） | +1 |
| 深度 L3 | +1 |
| 深度 L4 | +2 |
| 命中开放题概念（OQ 有对应口述题） | +1 |

实测分布：`w=5: 9 题 · w=4: 15 · w=3: 11 · w=2: 31 · w=1: 24`，每章都有 w≥4 的题。

### 组卷参数（HTML 页面工具栏）

| 参数 | 作用 |
| :--- | :--- |
| 题量 | 本次组多少题 |
| 权重 | 按 `w` 加权抽样（关掉=等概率） |
| 去重 | 同一 `concept` 只取一题（关掉=可重复考点） |
| 种子 | 同一种子 → 同一份卷子（可复现）；「换一批」重生种子 |

### 两种部署形态（同一份文件）

| 形态 | 打开方式 | 题库来源 | 适用 |
| :--- | :--- | :--- | :--- |
| **单文件** | 双击 `index.html`（`file://`） | 内联 `BANK_INLINE` | GitHub Pages / 发文件给同学 / 离线 |
| **双文件** | 起 http 服务访问 | `fetch('./bank.json')` | 本地改题即时生效，不用 rebuild |

> 页面优先用内联数据；内联为空时自动回退到 `fetch('./bank.json')`。
> 这样**既能单文件部署，又不牺牲改题效率** —— 直接双击能用，是因为数据已经躺在 HTML 里了。

## 多端同步（错题池 / 组卷参数 / 答题历史）

**为什么需要**：答题状态存在浏览器 `localStorage` 里，换设备就没了。题库正文由 git 管，
但「你错过哪些题」必须跨端带上。

**怎么用（每台设备各做一次）**

1. 打开测验页 → 点工具栏右侧 **☁️ 同步** → 展开面板
2. 去 GitHub → Settings → Developer settings → Personal access tokens 生成 token，
   **只勾 `gist` 一项**（classic token；fine-grained 选 `Gists: write`）
3. 把 token 粘进面板 → 点「连接」→ 自动上传，之后每台设备填同一个 token 即可互通

**同步范围**

| 同步（走 Gist） | 存储 key |
| :--- | :--- |
| 错题池 | `aag_quiz_wrong_v3` |
| 组卷参数 | `aag_quiz_compose_v1` |
| 答题历史（每次交卷的时间/正确率） | `aag_quiz_hist_v1` |

**不同步**：题库正文（git 管）、答题卡折叠态（纯 UI 偏好）。

**设计要点**

- **凭证隔离**：token / gistId 存在 `aag_quiz_cs_v1`，**绝不上云、绝不写进页面文件**。
  上云 payload 只含 `{app, version, exportedAt, wrong, compose, hist}`。
- **冲突策略**：拒绝覆盖 + 手动确认。云端比本机新时，自动上传静默暂停并提示你手动下载。
- **安静通道**：同步动作自身写状态（更新 `syncedAt`）标记为 silent，
  不更新 `lastLocalWrite`，否则会形成 `写状态→判定有改动→上传→写状态` 的死循环烧光限流。
- **设备关联**：新设备只有 token、没有 gistId 时，按 Gist 描述自动找回同一份（取 `updated_at` 最新），
  避免误建第二个 Gist 导致「A 传的 B 看不到」。
- **无需后端**：`api.github.com` 官方支持任意 origin 的 CORS 且放行 `Authorization` 头，浏览器可直连。
  `file://` 双击打开也能用（拦截的是本地文件 fetch，远程 HTTPS 允许）。

> ⚠️ token 存在 localStorage，任何能跑在该页面的脚本都能读走 → **务必只勾 `gist` 权限**。
> 仓库是 public，但 token 不在文件里，只在你的浏览器里。
